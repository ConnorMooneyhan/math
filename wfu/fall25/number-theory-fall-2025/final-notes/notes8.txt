Class notes - MTH 346/646 - 9/18/25

This file has notes about how to use Magma to do computations
with the stuff we've talked about so far in MTH 346/646.

In Magma, every line has to end with a ;
Every assignment is done with := . For example:

> a := 4;
> b := 2;
> a/b;
2

Now, Magma knows that a/b = 2, but because division is involved,
Magma is thinking of a/b as a rational number.

> Factorization(a/b);

>> Factorization(a/b);
                ^
Runtime error in 'Factorization': Bad argument types
Argument types given: FldRatElt

Since a/b is a rational number (Magma says it has type FldRatElt) it won't
compute the prime factorization. We need to tell Magma to think of a/b as
an integer.

> Z := Integers();
> c := Z!(a/b);

The expression Z!(a/b) tells Magma to think of (a/b) as an element of Z. 
This "coersion" of telling Magma to take an object of one type and think of it as another
type is very common.

> c;
2

Now it will factor it.

> Factorization(c);
[ <2, 1> ]

Magma is good at doing complicated exact arithmetic.

> Factorization(2^60-1);
[ <3, 2>, <5, 2>, <7, 1>, <11, 1>, <13, 1>, <31, 1>, <41, 1>, <61, 1>, <151, 1>,
<331, 1>, <1321, 1> ]

Magma can tell you if a number is a square.

> IsSquare(1089);
true 33
> IsSquare(9801);
true 99
> chk, sqrroot := IsSquare(5234^3 + 17);
> chk;
true
> sqrroot;
378661
> F := GF(37);

Here F is F_37 = Z/37Z is the field of size 37.

> a := (F!2);
> a^18;
36

Of course 2^18 isn't equal to 36, but 2^18 = 36 (mod 37).

> R<x> := PolynomialRing(Rationals());
> g := x^3 - 2*x + 3;

Magma can factor polynomials

> g := x^3 - 2*x + 1;
> Factorization(g);
[
    <x - 1, 1>,
    <x^2 + x - 1, 1>
]

Now let's work with some conic sections.

> P2<x,y,z> := ProjectiveSpace(Rationals(),2);
> f := x^2 + x*y + y^2 - 109*z^2;
> C := Conic(P2,f);
> BadPrimes(C);

The set BadPrimes is the set of primes p we can use to show there are
no solutions (by reducing mod p). In this case, the set is empty.

> HasRationalPoint(C);

Magma finds a rational point on our conic.

> Evaluate(f,[5,7,1]);

> BadPrimes(C);

This conic has bad primes,

> HasRationalPoint(C);

Now, let's use Magma to find maps between a plane cubic and an elliptic curve

> R<x,y,z> := PolynomialRing(Rationals(),3);

Curve over Rational Field defined by

Something weird happened here. The dollar signs show up as place holders
for variables in a polynomial ring. We haven't named the variables in the
polynomial ring, so Magma doesn't know what to call them.

Is this a rational map or a morphism? The "base scheme" (or base locus)
of a rational map is the set of points in the domain where the map is undefined.

> BaseScheme(mp);
Scheme over Rational Field defined by
$.3,
$.1,
$.1 + $.2,
$.1^3 + $.2^3 - 6*$.3^3

> RationalPoints(BaseScheme(mp));
{@ @}

This is the empty set. There are no rational points on the curve C where mp is not defined.
(In fact, there are no complex points where C is undefined.) So mp is a morphism.

> E;

This isn't the nicest elliptic curve

> E2, mp2, invmp2 := WeierstrassModel(E);

Elliptic Curve defined by y^2 = x^3 - 243 over Rational Field

That's better.

Let's build one map that sends points on C to points on E2

bigmap := mp*mp2;

Magma composes maps from left to right. So bigmap means "do mp to a point on C, and
then apply mp2 to the resulting point on E."


Let's take the point (17/21 : 37/21 : 1) and map it to E2.

> P := C![17/21,37/21,1];
> bigmap(P);
(7 : -10 : 1)

> chk, bigmapinv := IsInvertible(bigmap);
> chk;
> bigmapinv;

Is this a morphism, or just a rational map?

> RationalPoints(BaseScheme(bigmapinv));
{@ (0 : 1 : 0) @}

There is a point where bigmapinv isn't defined.

> Degree(BaseScheme(bigmapinv));

Now, let's do an example where we map a curve in the form y^2 = quartic
to an elliptic curve.

> R<x> := PolynomialRing(Rationals());

> C;
Hyperelliptic Curve defined by y^2 = x^4 + x^3 + x^2 + x + 1 over Rational Field

y^2 = x^4 + x^3*z + x^2*z^2 + x*z^3 + z^4

Now, let's have Magma map a curve defined by two quadratic equations to an
